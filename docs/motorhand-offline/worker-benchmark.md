# 工作线程数的离线对照

本次采用相同机器亲和范围，顺序运行 0、2、6 个 Mochi 工作线程的 demo。场景为固定腕部、掌心锁定、90 mm 软球、硬度 1、demo grip 0.8；每组稳定 5 秒后录制约 8 秒，控制目标 100 Hz，输出关闭。`0` 表示单线程物理求解。每组均从新的 demo 进程启动，独立记录，退出后清除临时文件。

| 物理工作线程 | 控制采样数 | 不同物理帧数 | 接触帧龄中位数 / P95 / P99 / 最大值 (ms) | 帧间隔中位数 / P95 / P99 / 最大值 (ms) | 录制丢帧 |
|---:|---:|---:|---|---|---:|
| 0 | 794 | 172 | 70.96 / 141.21 / 161.32 / 161.57 | 40.01 / 78.74 / 83.99 / 161.40 | 0 |
| 2 | 794 | 316 | 40.82 / 60.71 / 61.05 / 71.13 | 24.99 / 31.27 / 34.36 / 36.12 | 0 |
| 6 | 793 | 581 | 20.76 / 30.85 / 40.86 / 44.80 | 13.47 / 16.86 / 21.84 / 32.10 | 0 |

当时真机预览及其他 pytest 进程并发运行；三组依次运行，没有随机化或重复，软体和接触状态也可能略有不同。数字只用于本机此次离线对照，不代表严格相同物理轨迹或佩戴反馈表现。保留现有 6 线程配置；不要以此结果推断真机断联已经解决。

复现：

```bash
.venv/bin/python tools/experiments/motorhand_worker_benchmark.py
```

原表来自旧版硬度 1 的弹性球。统一材质后的脚本选择 0.99 以继续测量软体负载。脚本启动临时 demo 进程，不连接真机，不启用力反馈。脚本读取当前工作区的入口源码，在临时目录覆盖工作线程数；当前线程初始化代码如果改变，脚本会立即报错，避免静默测量错误配置。为确保后台不存在多余的物理仿真进程及减少 CPU 干扰，建议在受控环境重复并随机化组次。脚本 stdout 输出每组的完整统计；不保留逐轴录制，避免将临时诊断数据混入用户已有录制。
