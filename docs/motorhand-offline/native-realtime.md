# 本地抓握 C++ 实时链路验收

`--local-grasp` 默认由 C++ 处理 G4 串口采样、零偏与行程换算、闭链求解、Mochi 物理子步、抓握物体运动、接触投影、力反馈合成和定时提交。物理线程按实际输入的时间戳发布接触结果。100 Hz 控制线程在提交前再次核对使能和场景版本，G4 检查按最旧输入计算的 100 ms 截止时间。启动与资源配置、网页和 CSV 由 Python 管理，网页快照延迟不影响控制线程的调度。

## 同场景比较

基线为提交 `c41046e` 的默认混合实现。测试使用 FP32、相同的 12 轴 demo 闭合动作、`nominal-plus`、1/240 秒物理步长、6 个工作线程，并在保持段录制约 8 秒。这些指标来自控制周期采样。帧龄指电机控制处理该接触帧时，其最旧输入已有多久。

| 场景 | 版本 | 帧龄 P50 / P95 (ms) | 超过 100 ms 的控制周期 | 松开后 J5 中位数 (N·m) |
|---|---|---:|---:|---:|
| 89 mm 刚性方块 | 基线 | 10.63 / 20.79 | 0 / 800 | 0 |
| 89 mm 刚性方块 | C++ | 10.01 / 20.00 | 0 / 810 | 0 |
| 90 mm 软鸭灯 | 基线 | 61.09 / 82.29 | 4 / 801 | 0 |
| 90 mm 软鸭灯 | C++，单独复测 | 50.00 / 70.00 | 0 / 811 | 0 |
| 90 mm 软鸭灯 | C++，同时有其他计算 | 50.01 / 70.00 | 12 / 812 | 0 |

硬方块的 J5 保持段名义力矩中位数在两版均为 8.477 N·m。鸭灯在并发负载下的最大帧龄为 140 ms，触发原有过期保护。较慢的接触求解和系统调度仍会消耗有效期，各次物理运行的接触状态也会有差异。[逐次统计](native-link-benchmark.json)

对 243 组历史编码器输入逐帧回放，闭链求解 P95 从 1.866 ms 降至 0.063 ms，闭链导数计算从 2.423 ms 降至 0.209 ms，树关节角最大绝对差小于 9×10⁻¹⁵ rad。极端输入求解失败时，本周期输入失效。

## 从串口到线缆的检查

使用真正的 G4 SDK 与伪终端模拟网关，运行正常的本地抓握入口。最终硬方块试验共记录 582 个控制周期，丢弃 0。从请求启用到线缆上第一个 MIT 帧约 194 ms。2 秒保持段得到 200 个控制采样和 395 个 J5 总线帧，反馈中断和超期接续均为 0。张手后的 12 位零扭矩编码在解码端有约 0.0024 N·m 的量化误差。显式停止后未观测到非零指令，全部 12 轴继续收到位置查询。

隔离测试另外覆盖观察者持有 Python GIL 300 ms、同帧重复读取、5° 单轴回撤、场景切换、数据停止应答和伪串口拔插。单轴丢样与操作系统报告物理断开分别处理。物理重连在当前会话取消旧使能及零位，重新标零和手动启用后恢复出力。物理断线期间无法从主机向已经失联的设备发送卸力命令。这些试验覆盖软件和协议行为，佩戴闭环及不同主机负载需分别测量。

真机预览使用相同 C++ 入口，出力关闭。7 秒内取得 140 个独立网页控制快照，12 轴持续在线，串口重连计数为 0，控制丢周期累计值没有增加。控制周期计算 P50/P95 为 0.012/0.025 ms，接触帧龄 P50/P95 为 21.75/32.46 ms。这些统计来自面板快照，未测量佩戴出力和长时间工作。

## 原版二阶魔方的握持与松手

在固定腕部、73 mm、硬度 1、掌心锁定的原版魔方上，仅修改与手的碰撞查询方向。手部采样点查询八个角块的原始外壳 SDF；内芯仅参与魔方内部接触。相同固定步轨迹的保持段，物理求解 P50 / P95 从 406.9 / 437.8 ms 降至 3.0 / 5.1 ms。接触离散方式变化会影响力矩，应分别评估佩戴手感。

正常 C++ 入口的 8 秒离线录制得到 761 个保持周期，接触帧龄 P95 为 20.02 ms，无过期，无录制丢帧。J5 名义力矩绝对值中位数 3.74 N·m，全轴名义峰值 7.13 N·m。松手窗口内全轴名义峰值为零。5 秒真机预览测得子步 P95 为 6.02 ms，佩戴姿态未固定，出力关闭。

## 红方块变尺寸与同帧反馈

用真实物理模型在合指姿态将红方块从 76 mm 扩至 123 mm，旧放置规则使当前手部表面点最多穿入方块约 18 mm，首个子步的原始投影约 2581 N·m。该数值来自仿真。按当前仿真手和驱动目标手共同确定新物体位置后，首步投影归零，随后的 23 步最大投影约 0.00036 N·m。空间不足时物体沿掌面法线临时避让；两组手形均已让开且物体脱离接触后，通过新的接触场景版本归位。正常入口的红方块复抓出现位置补偿，张手后的有效窗口内 12 轴名义力矩均归零。

使用实际 SDK 和伪网关走正常入口时，自由开合的每周期最大轴角差 P95 为 0.014 rad，未产生接触阻力。受阻保持的 J5 同帧角差中位数为 0.102 rad，位置项达到 2.0 N·m，总线指令约 8.50 N·m；首次确认无反力的控制周期名义及下发力矩均为零。

同一控制周期的表格与 CSV 保留当前输入、生成接触帧的输入和仿真回读。`sim_minus_input_rad` 为后两者的有符号差。三维画面的手姿、接触和反馈按实际物理子步时间戳配对，未被控制线程采用的物理帧显示等待。拖动尺寸时用线框提示待提交的范围，实体和拾取保持在真实仿真几何上。

|---|---:|---:|---:|---:|
| 2.060 | 1 | 54.11 | 51.42 | 104.13 |

这 7 个周期里，最新编码器数据年龄最多 3.69 ms，控制计算最多 0.062 ms。整段串口重连为 0，控制漏拍计数没有增加。809 个有效周期内，12 轴接触投影均为零。输入用于生成接触帧时已耗去一部分期限，等下一帧时才跨过 100 ms；原始 CSV 没有逐子步求解器剖析数据。

四种独立色块使用同一碰撞 SDF。旧配置同时查询手→色块和色块→手，负载试验证实后一个方向的查询耗时很大。现在仅移除该反向查询，保留原模型、尺寸和与桌面的双向接触。固定合拢轨迹的握持子步 P95 从 26.87 ms 降到 1.00 ms，J5 原始投影中位数分别为 −0.2806 和 −0.2812 N·m，张手后均归零。

使用原录制的 12 轴编码器和实际时间间隔做伪串口对照。摆位顺序会影响接触，先将手置于录制初始姿态再放置方块，另测标准合握和张手；请在仓库根目录运行：


## 108 mm 刚体鸭灯的指令跳变

2026-11-22 的 `grasp-20261122-213407-cbtnozp2.csv` 有 1087 个控制周期。中断计数由 30 增至 37，短超期接续由 86 增至 143，接触帧龄 P95 为 103.46 ms、最大 132.29 ms。相邻两个周期均有下发值时，共有 34 个周期至少一轴力矩跳变超过 1 N·m，全部发生在接续时。第 4.50→4.51 秒 J8 指令 +4.93→0 N·m，接触投影约 −0.164 N·m，位置项为 −2 N·m，回撤权重为 1。旧指令到期后，控制器在新帧上从零渐入。该段录制串口重连为 0，控制节拍漏拍计数无新增。

## 软鸭灯的保护停机与临期更新

再次报告强烈跳变时，在线场景为 108 mm 鸭灯、硬度 0.98。该次冲击没有对应的真实下发录制；当时会话累计一次“仿真使用的编码器样本过期”和一次接续。此前 10.86 秒的附件来自硬度 1，用它的输入轨迹在 0.98 材料上复测。

若上批 MIT 的期限落在下一控制节拍之前，C++ 线程可等待物理帧发布通知。新帧先到时重新读取编码器并运行一次完整控制更新；SDK 持锁校验新期限、原批次及原期限，避免看门狗已卸力后用另一批命令补发。运行中已提交的批次真正过期或输入失效时主动卸力并锁存。恢复的数据或切换场景均不能清除该保护，操作者须先停止，再清楚地重新请求启用并经过连续帧检查。若控制线程偶发停顿但输入仍有效，下一次建力最多使用一个控制周期的斜率和滤波步长。单轴明确松手立即归零。

实际 SDK + 伪串口的临期用例在旧截止前约 4 ms 送达新帧，三个窗口内保持 J5 连续下发；真实过期时，后续有效帧持续 400 ms 仍保持卸力。合成 75 ms 未到期停顿用例中，恢复时的第一条新负载指令由 4.50 降到 0.48 N·m。

软鸭灯使用由原体网格节点驱动的接触蒙皮。最终资产保留 4059 个四面体、1328 面显示网格，接触网格为 672 面。保持 20 mm 与 150 mm 两端的尺寸验收容差。接触离散有变化，在 108 mm 模型上，原表面到蒙皮的双向采样距离均小于 1.7 mm，实际分布与手姿有关。

最终模型在独立复测中回放 1086 个周期，1086 个周期均处于出力，0 超期、0 中断、0 自动接续；帧龄 P95/最大为 54.79/72.88 ms。同轴相邻总线包（间隔不超过 20 ms）的最大扭矩变化为 0.484 N·m。另做 2 秒合握和松手，保持段有非零下发，完全张手后 12 轴均为量化零。早期 664 面候选与编译负载并发时发生过一次真的过期，之后一直保持卸力；没有将那段停止后的零输出计作抖动改善。[最终回放结果](soft-duck098-replay.json)

这是真实 SDK 的台架协议验证，没有使用佩戴者复现这次强跳，也不代表任何负载下均能保持出力。复现命令使用无物理设备的伪终端：
